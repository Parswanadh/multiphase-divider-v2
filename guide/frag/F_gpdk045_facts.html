Facts verified from the real gpdk045_v_6_0 package

The statements below were checked against the files of the installed gpdk045_v_6_0 package, not taken from a manual. Where something is still unconfirmed, the section says so.

Package layout

  • The top level holds assura, diva, gpdk045 (the OpenAccess library, with cell data in OA format), models, pvs and soce, plus cds.lib, pvtech.lib and assura_tech.lib.
  • The library entry in cds.lib is DEFINE gpdk045 ./gpdk045. The file also defines gpdk045_pvs (./pvs) and gpdk045_av (./assura).

Spectre models

  • models/spectre/gpdk045.scs defines the corner sections tt, ff, ss, fs and sf, plus mc. Each corner includes the per-device files (gpdk045_mos.scs, gpdk045_diode.scs, and so on) with the same corner name.
  • Include it in a netlist with include "<path>/models/spectre/gpdk045.scs" section=tt.
  • The 1.0 V standard-Vt NMOS is the inline subcircuit g45n1svt (d g s b) with parameters l w multi nf factor. It is built on a BSIM4 model card named nch.
  • Other device subcircuits in gpdk045_mos.scs: g45n1hvt, g45n1lvt, g45n1nvt (native), g45n2svt and g45n2nvt (2.0 V NMOS), and PMOS g45p1svt, g45p1hvt, g45p1lvt and g45p2svt.
  • The Virtuoso library cell nmos1v exists with the views auCdl, auLvs, hspiceD, ivpcell, layout, spectre and symbol. The view data is binary, so I did not confirm from the files that it netlists to g45n1svt. Check the netlist of an nmos1v instance in the GUI.
  • All ten device subcircuits contain the gate-resistance sub-model xrg. That sub-model is ressnpoly_rg or ressppoly_rg, and it is written with a bsource behavioural source. Spectre therefore has to compile an AHDL module the first time it reads the model.
  • Sections in gpdk045_mos.scs: stat_mis_* (mismatch statistics for Monte Carlo: stat_mis_std, _hvt, _lvt, _na, _18, _18na), the corners tt ff ss fs sf, and the same corners with the _hvt, _lvt, _na and _18 suffixes.

Netlist skeleton

This is the skeleton from spectre/divider_gpdk45.scs. The include path is the one written in that file. Replace it with the location of the package in your VM.

simulator lang=spectre

include "/home/buet/pdk/gpdk045_v_6_0/models/spectre/gpdk045.scs" section=tt

subckt DLATCH (D Db CK CKb Q Qb VDD VSS NBIAS)
  R1 (VDD Q)  resistor r=rl
  R2 (VDD Qb) resistor r=rl
  M1 (Q  D  xs   VSS) g45n1svt w=240n l=45n
  M2 (Qb Db xs   VSS) g45n1svt w=240n l=45n
  M5 (xs CK tail VSS) g45n1svt w=240n l=45n
  M3 (Q  Qb xh   VSS) g45n1svt w=240n l=45n
  M4 (Qb Q  xh   VSS) g45n1svt w=240n l=45n
  M6 (xh CKb tail VSS) g45n1svt w=240n l=45n
  M7 (tail NBIAS VSS VSS) g45n1svt w=480n l=90n
ends DLATCH

Troubleshooting: AHDL compile crash in the CentOS 6.5 VM

On the 32-bit CentOS 6.5 guest (MMSIM 12.1), Spectre crashed while compiling the AHDL module for instance bsource_1 inside g45n1svt, with:

ERROR (VACOMP-1008): Cannot compile ahdlcmi module library
FATAL (SPECTRE-18): Segmentation fault

The cause was found in two parts. Cadence's bundled perl (MMSIM121/tools.lnx86/perl/bin/cdsPerl) is a 64-bit binary, and the 32-bit guest cannot run it (cannot execute binary file). So ahdlcmigenclist.pl failed and the generated makefile had no sources. The guest also had no gcc. The fix below was applied in that order.

  1. Install gcc 4.4.7 and glibc-devel from the CentOS 6.5 vault RPMs. The guest has no working yum SSL, so use the ISO as a local repository: 
    mount -o loop /path/to/CentOS-6.5-i386-bin-DVD1.iso /mnt/cdrom
yum --disablerepo='*' localinstall /path/to/vault-rpms/gcc-4.4.7*.rpm /path/to/vault-rpms/glibc-devel-*.rpm
gcc --version
    The RPM file names depend on the ISO you use. Check that gcc --version reports 4.4.7 before continuing.
  2. Replace the perl launcher with a shell wrapper that calls the system perl. Keep the original as perl.orig: 
    cd MMSIM121/tools.lnx86/perl/bin
mv perl perl.orig
printf '#!/bin/sh\nexec /usr/bin/perl "$@"\n' > perl
chmod +x perl
./perl -v
  3. Run the netlist again. The AHDL compile of bsource_1 should now succeed. The simulation result after this fix is reported in the project status, not here.

What this means for you

  • Use the corner names tt, ff, ss, fs and sf for the PVT sweep. Do not invent section names.
  • Use the device name g45n1svt in the netlist and expect the first Spectre run to pause on the AHDL compile. A crash at that point is the VM problem above, not a netlist error.
  • Use stat_mis_* only with a Monte Carlo analysis. The corner sections give a deterministic process corner.
Model names are now checked, the GUI is not The VERIFY items in the earlier sections about the model path, the section name and the device name are resolved by this section: the sections are tt, ff, ss, fs and sf, and the device is g45n1svt with the nmos1v cell. The menu paths and the Virtuoso CDF parameter names are still unverified and must be checked in the GUI.

Second blocker found after the Perl fix: the bundled compiler

With Perl fixed the AHDL build started compiling but stopped with gnumake: *** [obj/optimize/5.0/bsource_1_libahdlcmi.so] Error 126 (cannot execute). In MMSIM121/tools.lnx86/cdsgcc/gcc/4.4/bin the entries gcc, ld and c++filt are symlinks to a wrapper that starts a bundled compiler that does not run on the 32-bit guest. The fix that made Spectre complete with 0 errors and 0 warnings on gpdk045 was to back up that directory and point the three entries at the guest's system tools (gcc 4.4.7 installed from the CentOS 6.5 vault RPMs):

cd ~/cadence/MMSIM121/tools.lnx86/cdsgcc/gcc/4.4
cp -a bin bin.orig
cd bin
ln -sf /usr/bin/gcc gcc
ln -sf /usr/bin/ld ld
ln -sf /usr/bin/c++filt c++filt
Both fixes are needed, in this order (1) system gcc and glibc-devel installed, (2) perl/bin/perl wrapper changed to exec /usr/bin/perl "$@", (3) the three symlinks above. Only the first Spectre run pays the AHDL compile cost; later runs reuse the compiled library for the same netlist directory name.
