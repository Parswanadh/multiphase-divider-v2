Schematic entry: DLATCH cell, symbol and divider_core

about 60-90 min This section builds the circuit bottom-up: first the differential D-latch (DLATCH), then its symbol, then the four-instance ring (divider_core). Keep every net name identical to the reference netlists spectre/divider_gpdk45.scs and spice/divider_45nm_proxy.cir in the repository, so you can diff your extracted netlist against them later. Note that the SPICE proxy uses generic models and is only a topology cross-check, not gpdk045 data.

Library and device names Create (or reuse) a design library attached to the gpdk045 technology library: File > New > Library, then attach to the existing technology library when prompted. In the component browser (i in the schematic editor) the core 1.0 V NMOS is normally nmos1v (cell in library gpdk045, view symbol). Verify the exact cell name and the names of its instance parameters (typically width, length and number of fingers) in the Property editor (q) of the placed instance. Do not type parameter names from memory; use the ones your CDF shows. Thick-oxide devices (nmos2v) are not wanted here.

1. The DLATCH schematic

  1. In the Library Manager select your library, then File > New > Cellview. Cell name DLATCH, view schematic, type Schematic (Virtuoso Schematic Editor L or XL, verify in your version).
  2. Place seven nmos1v instances with i and name them exactly M1 to M7 (property Instance Name, shortcut q). Use consistent orientation: sample pair left, hold pair right, tail at the bottom.
  3. Set sizes on each instance (starting values, to be tuned later):
    DeviceRoleWLFingers
    M1, M2sample (input) pair240n45nverify (start with 1 or 2)
    M3, M4hold (cross-coupled) pair240n45nsame as M1/M2
    M5sample switch (gate CK)240n45nsame
    M6hold switch (gate CKb)240n45nsame
    M7tail current source (gate nbias)480n90nverify
    Match M1/M2 and M3/M4 exactly (same W, L and fingers); the 8-phase accuracy depends on this symmetry.
  4. Place two resistors R1 and R2 (VDD to Q, VDD to Qb), 8 kOhm each as a starting value (a generic-model pre-check failed to divide at 1.5 kOhm because the hold pair needs gm x R above 1; tune from here). For the first functional simulation use the ideal res from analogLib. When you move to layout, replace them by a PDK resistor (a poly or well resistor from gpdk045; verify which one is available and its sheet resistance) and recompute W/L for your final R. Parasitic capacitance of that resistor then appears in post-layout results.
  5. Wire the netlist exactly as in the table below. Use w for wires and l (wire name) to label every net. Do not rely on touching wire ends; always label the internal nodes xs, xh and tail.
  6. Add pins with p: inputs D, Db, CK, CKb; outputs Q, Qb; inouts VDD, VSS; and a bias input (see the warning below).
  7. Run Check and Save (Shift+X). Fix every warning; a floating bulk or an unconnected pin is a real error here.
The bias pin The pin list in the paper-based description is D, Db, CK, CKb, Q, Qb, VDD, VSS, but M7 has its gate on nbias. Either add a ninth pin (recommended name VB, tied to nbias inside DLATCH) or declare a global net. A dedicated pin is better: it appears in the symbol, you can drive it from vdc in the testbench, and the LVS interface stays explicit. If you use a different name from the reference netlist, note the mapping in your report.

2. The DLATCH symbol

  1. With DLATCH schematic open: Create > Cellview > From Cellview. Accept the default view name symbol and the pin placement dialog.
  2. Place inputs on the left (D, Db, CK, CKb, VB), outputs on the right (Q, Qb), VDD on top and VSS at the bottom. Click OK; the symbol editor opens.
  3. Replace the default rectangle if you like (a box is fine), add the text DLATCH, then Check and Save.
  4. Reopen the schematic and confirm that the symbol pins and the schematic pins match one-to-one (a mismatch gives an error when you place the symbol).

3. The divider_core schematic

  1. New cellview divider_core, view schematic.
  2. Place four DLATCH symbols (i, Library = yours, Cell = DLATCH, View = symbol). Name them XD1, XD2, XD3, XD4.
  3. Wire per the table below. Label every connection with a wire name, including short stubs. In particular write Q1b, Q2b and so on as proper names; do not use special characters.
  4. Add top-level pins: CK, CKb, VB (inputs), VDD, VSS (inouts), and Q1, Q1b, Q2, Q2b, Q3, Q3b, Q4, Q4b (outputs).
  5. Check and Save, then create a symbol for divider_core with Create > Cellview > From Cellview (needed for the testbench).

Easy mistakes in this wiring XD2 and XD3 receive the clocks swapped (pin CK gets net CKb). XD1 and XD4 receive them straight. The data crossing is also asymmetric: XD2 takes (Q1b, Q1) while XD3 takes (Q2, Q2b). A single swapped pair breaks the divide-by-two behaviour without any warning from the tools, so compare against the reference netlist before simulating.

Wire naming, bulk connections and LVS

  • Name every net in both the cell and the parent. Spectre netlists use these names, so your waveform viewer shows /Q1 rather than net012, and the OCEAN/Calculator expressions in the next sections stay stable between edits.
  • Bulk connections: connect every NMOS bulk to VSS explicitly with a wire (not by a global such as gnd!). Implicit bulks lead to a floating or wrongly tied well and to LVS mismatches at the substrate.
  • Pins as the LVS interface: LVS compares the pin names of the schematic with the text labels (pin shapes) in the layout. Names such as VDD, VSS, CK, CKb, Q1 must be written identically (case sensitive) on a metal label in the layout. A mismatch shows up as "pin not found" or as a merged net.
  • Dummy devices: if you later add dummy gates or dummy fingers for matching or density, either also place them in the schematic (gate, source and drain tied to VSS) or confirm that your LVS deck ignores them. Decide this now; retrofitting a schematic after layout is slow.
  • Do not use the same name for two things: an internal node called Q in DLATCH is local; at top level the hierarchy separates it. Never connect two different pins with the same label by accident (for example CK and CKb typed with different case on a net).

Testbench tb_divider and simulation setup

about 45 min The testbench is a separate cell. It contains the supply, bias, a complementary clock pair, load capacitors and nothing of the DUT internals. Keep all numbers as design variables so that the frequency sweep and corner runs need no schematic edits.

1. Build the schematic

  1. New cellview tb_divider (view schematic). Place the divider_core symbol as DUT.
  2. From analogLib place: vdc (named V0) between VDD and gnd; a second vdc (V1) for the bias VB; two vpulse sources (VCK and VCKB); eight cap instances (CL1 to CL8); and one gnd. Connect VSS of the DUT to gnd (node 0).
  3. Name the supply source exactly V0; the power expression in the next section assumes /V0/PLUS.
  4. Label nets: VDD, VB, CK, CKb and the eight outputs Q1 ... Q4b.
  5. Check and Save.

2. Source parameters

Define ADE design variables (see below) fin, T, tr, vdd and vb, and enter them in the CDF fields. If your CDF field does not accept expressions such as T/2-tr, define pw and tdel as separate variables (verify in your version).

The pulse width is the time at the high level; with equal rise and fall times a 50 % duty cycle needs T/2 - tr. When the clock period shrinks during the frequency sweep, keep tr at most T/10 (for example tr = min(20p, T/10)) so the pulse width stays positive.

Cleaner complement A delayed copy is complementary only if the edges are symmetric. An alternative that gives an exact complement is to set the CKb source to v1 = 1.0 V, v2 = 0 V, td = 0 and all other fields equal to the CK source. Then the two edges cross at the same instant at VDD/2. Choose one approach and state it in the report; the delay version matches the "half period" wording of the task.

3. Loads and bias

  • Place 5 fF to 10 fF capacitors from each of the eight output nodes to ground. They represent the following buffer, probing pads and routing. Start with 10 fF (the value used in the pre-check netlist); use 5 fF as a sensitivity case. A larger load raises dynamic power, increases CK-to-Q delay (so PDP gets worse), and lowers the maximum input frequency. Always report the load value with your numbers.
  • The bias vb sets the tail current. A first guess is 0.8 V (0.55 V gave only tens of microamps in a generic-model pre-check, so check your own tail current); tune it so the output swing is about 300 to 400 mV (check the DC operating point) and so that M7 stays in saturation (see troubleshooting).
  • Edge rates are part of the stimulus: with tr = 20 ps the clock is a trapezoid, increasingly so as you raise fin. Do not use the ideal pulse with zero rise time; it breaks timing and causes convergence trouble.

5. Initial conditions: why and how

This divider is a regenerative ring. With all nodes starting from the DC operating point and with a perfectly symmetric netlist, Spectre can find a symmetric, metastable solution (Q equal to Qb in every latch) and stay there: the clock toggles but the outputs never split. Real circuits start because of noise; a noise-free simulation does not. Two remedies exist:

  1. Initial conditions (ic), preferred. They force the node voltages at time zero. In ADE: Simulation > Convergence Aids > Initial Condition (some versions use Setup > Initial Condition; verify in your version) and add the nodes listed below. The equivalent Spectre statement is 
    ic Q1=1.0 Q1b=0.7 Q2=1.0 Q2b=0.7 Q3=0.7 Q3b=1.0 Q4=0.7 Q4b=1.0
  2. Node set (nodeset), only a hint for the DC solver (Simulation > Convergence Aids > Node Set, verify). It helps convergence but does not remove the metastable solution if that is also a valid DC point, so use ic for forcing.

The logic values in the task statement (Q1 = 1, Q2 = 1, Q3 = 0, Q4 = 0, each with its complement inverted) map to voltages as follows. A CML-style latch is not rail to rail: the high level is VDD, the low level is VDD minus the swing (approximately Iss times R). Use your own DC value after the first run.

NetLogicVoltage (estimate)

Q1b0vdd - swing, about 0.7 V
Q211.0 V
Q2b0about 0.7 V
Q30about 0.7 V

How to choose the initial state Pick a state that is one of the valid states of the divider's counting sequence, not an arbitrary pattern. Latches which are in "hold" during the first clock phase keep their ic value; latches in "sample" are overwritten within a gate delay. Take the pattern from the ic or nodeset lines of spectre/divider_gpdk45.scs if present (verify), because it was chosen for that exact clock assignment. If the pattern you try does not start division, rotate it: try each of the other cyclic states (1100, 0110, 0011, 1001 for Q1..Q4, and also the inverted set). Exactly which one is legal depends on the clock polarity of each latch, so test them one by one rather than by theory.
Using ic from the netlist directly An advanced alternative is the Spectre tran option skipdc=yes (verify in your version), which starts the transient directly from the ic values without a DC solve. Use this only if the normal run still lands on the symmetric solution.

6. Run and first checks

  1. Press Netlist and Run (green play). Open Results > Direct Plot > Main Form or the waveform viewer. Plot /CK, /Q1, /Q1b.
  2. Confirm that Q1 toggles once per two clock periods (frequency fin/2).
  3. Then plot all four Q and Qb to see the 8 phases. Detailed measurements follow in the next section.

If the circuit does not divide

StepAction
1Check the ic statements actually reached the netlist: Simulation > Netlist > Display and search for ic (verify the menu). A typed node name that does not exist is silently dropped in some flows.
2Kick the clock: delay CK start by 100 to 200 ps (td of VCK) with VCKB following, so the circuit settles from the ic state before the first edge. Alternatively add a short extra pulse on one data node (a current pulse or a brief voltage ramp of 50 mV on Q1 for 20 ps) to break symmetry.
3Check clock polarity in XD2 and XD3 (swap of CK and CKb pins, see wiring table). A global polarity error produces constant outputs or an output at fin instead of fin/2.
4Check that CK and CKb are truly complementary and cross near VDD/2.
5Try a lower frequency (1 GHz) first. If it divides at 1 GHz but not at a higher target such as 3 GHz, you have a speed or swing problem, not a start-up problem.
6Try one of the other legal ic patterns.

Measurements in ADE and OCEAN

about 60 min All expressions below are entered in the ADE Explorer/Assembler output table (Outputs > Setup, then Open Calculator and Send To the table, or type directly into the Expression column). Use differential voltages for timing: the low level of a CML latch is not 0 V, so a fixed threshold such as 0.5 V may never be crossed. The differential zero crossing is independent of the common-mode level.

Window times Let T = 1/fin = 1 ns and Tout = 2T = 2 ns at 1 GHz. With a stop time of 40 T = 40 ns, measure between t1 = 20 T = 20 ns and t2 = 40 T = 40 ns. This window contains exactly ten output periods, which matters for averages. The numbers change when fin changes; define t1 and t2 as variables.

1. Output frequency

Define the differential signal first (or use VT("/Q1") - VT("/Q1b") inline), for example output name dQ1:

dQ1 = VT("/Q1") - VT("/Q1b")

;; period from two consecutive rising zero crossings (late in the run)
Tmeas = cross(dQ1 0 12 "rising") - cross(dQ1 0 11 "rising")
fout  = 1 / Tmeas
ratio = fout / fin                  ; expect 0.500

The Calculator also has frequency(wave) (verify in your version), which can be applied to clip(dQ1 t1 t2). A cross-based average is more robust: fout_avg = (N-1) / (cross(dQ1 0 N "rising") - cross(dQ1 0 1 "rising")) for a window clipped to the settled part. For a sanity check also measure the clock: fclk = 1 / (cross(VT("/CK") - VT("/CKb") 0 12 "rising") - cross(VT("/CK") - VT("/CKb") 0 11 "rising")).

2. Eight-phase delays and phase error

Take Q1 as the reference. For each stage k define dQk likewise and find the first crossing inside one output period after the reference edge:

tref = cross(dQ1 0 12 "rising")
t_k  = cross(clip(dQk tref (tref + Tout)) 0 1 "rising") - tref      ; k = 2, 3, 4
t_kf = cross(clip(dQk tref (tref + Tout)) 0 1 "falling") - tref     ; complement phases

The ideal phases are multiples of 45 degrees. With Tout = 2/fin one phase step is Tout/8 in time. The phase error of phase index k (k = 0 for Q1, 1 for Q2, 2 for Q3, 3 for Q4; k + 4 for the complement edges):

phase_err(k) [deg] = ( t_meas(k) - k * Tout / 8 ) / Tout * 360

In the calculator this is for example phErr2 = (t_2 - 1*Tout/8)/Tout*360. Expected nominal table:

Signal edgekIdeal delay vs Q1 risingIdeal phase

dQ2 rising1Tout/845 deg
dQ3 rising2Tout/490 deg

dQ1 falling (Q1b rising)4Tout/2180 deg

Do not assume the edge order is Q1, Q2, Q3, Q4 In a generic-model pre-check at 1 GHz the edges, sorted by time, came out as Q1, Q2, Q3b, Q4b, Q1b, and so on, in pairs of the form (a, 90 - a) degrees apart where a = 360 x Td x fin. The table above is the ideal target, not a prediction of which output lands on which slot. First sort the eight edge times, then compare consecutive differences with 45 degrees; scripts/measure_tran.py does exactly this for an exported waveform. The reason the steps are only 45 degrees when Tck is about 8 Td is explained in the pre-check findings section.
Direction of the sequence Whether Q2 lags Q1 by +45 deg or leads it by 45 deg (that is, appears at k = 7) depends on the circuit. If your measured pattern is reversed, use the mirrored index (k' = 8 - k) and say so in the report, or the "error" will show up as a false 90 deg. Look at the waveforms first, then fix the formula.

Report the maximum absolute phase error over the eight values and the RMS error.

3. Average power

The supply source V0 delivers current; Spectre defines the current into the positive terminal, so it is negative when the source supplies power. The average power over an integer number of output periods is:

P = average(clip(-i("/V0/PLUS" ?result "tran") * vdd  t1 t2))
;; equivalent: vdd * average(clip(-IT("/V0/PLUS") t1 t2))

Notes: (a) make sure t2 - t1 is a multiple of Tout (here ten output periods), otherwise the average has a ripple error of a few percent; (b) this is the core power only: the clock sources are ideal and not counted, and the bias source delivers almost no current; (c) quote the load capacitance used.

4. CK to Q delay

Use 50 % to 50 % thresholds. The clock threshold is vdd/2 (or the zero crossing of CK - CKb); the output threshold is the differential zero or the mid-swing level. A robust formulation is the difference of two crossings:

tCK = cross(VT("/CK") - VT("/CKb") 0 25 "rising")
tQ  = cross(clip(dQ1 tCK (tCK + T)) 0 1 "either")
Td  = tQ - tCK

The Calculator delay() form is (verify argument names in your version):

Td = delay(?wf1 VT("/CK") ?value1 vdd/2 ?edge1 "rising" ?nth1 25
           ?wf2 dQ1       ?value2 0       ?edge2 "either" ?nth2 1
           ?td2 tCK)

Which clock edge triggers the Q edge depends on the latch phase; the "either" edge picks the first output transition after the clock edge, and you should check by plotting once. If the delay is negative or larger than T, the search window is wrong.

5. Power-delay product with units

PDP = P x Td

Example: P = 2.34 mW and Td = 120 ps give PDP = 2.34 mW x 120 ps = 280.8 fJ. Since 1 mW x 1 ps = 10-3 W x 10-12 s = 10-15 J = 1 fJ, a number of mW multiplied by a number of ps gives fJ directly. (The numbers here only show the arithmetic; your own results will differ.) In the Calculator, work in SI units and convert at the end: PDP_fJ = P * Td * 1e15. Energy per divided cycle (P/fin) is a useful second figure.

6. fmax search

  1. Create a parametric sweep of fin. In ADE Explorer: Tools > Parametric Analysis (verify), variable fin, values such as 0.5G 1G 2G 3G 4G 5G 6G (start low and raise it; the maximum frequency in gpdk045 will differ from any generic-model estimate). In ADE Assembler: type the list in the Global Variables sweep field (1G 2G 3G ...) or add a parameter set.
  2. Make everything else scale with fin: T = 1/fin, stop time 40/fin, maxstep = T/100, tr = min(20p, T/10), and the measurement window t1 = 20 T, t2 = 40 T.
  3. Define "still divides" in terms of your measurements:
    • fout/fin within 0.5 +/- 1 % in the whole window (no skipped or extra transitions).
    • Differential output swing at least 50 % of its low-frequency value (or at least 100 mV peak differential).
    • Maximum phase error below a limit you state, for example 10 degrees (a second, looser limit for "divides but poor phases" is useful).
    • Outputs stay periodic over the last ten output periods (no slow amplitude decay).
  4. fmax is the highest fin that meets all criteria. Refine by bisection between the last good and the first failing frequency (e.g., 7 GHz and 8 GHz, then 7.5 GHz). Repeat for the minimum frequency; very low fin may fail because of the leaky or too slow hold phase, or may cause self-oscillation (verify).

7. OCEAN script

The simplest way to a working run section is Session > Save Script in ADE L (or the equivalent in Assembler; verify in your version), which writes the design, model files and variables. Append or replace the measurement part with:

simulator('spectre)
;; ... design(), modelFile(), desVar() and analysis lines from the saved script ...
analysis('tran ?stop "40n" ?errpreset "moderate" ?maxstep "5p")
desVar("fin" 1e9)  desVar("vdd" 1.0)  desVar("vb" 0.8)
temp(27)
run()

selectResults('tran)
fin  = 3e9
T    = 1.0 / fin
Tout = 2.0 * T
vdd  = 1.0
t1   = 20.0 * T
t2   = 40.0 * T

dQ1 = v("/Q1") - v("/Q1b")
dQ2 = v("/Q2") - v("/Q2b")
dQ3 = v("/Q3") - v("/Q3b")
dQ4 = v("/Q4") - v("/Q4b")

;; frequency
Tmeas = cross(dQ1 0 12 "rising") - cross(dQ1 0 11 "rising")
fout  = 1.0 / Tmeas

;; phase errors (degrees), assuming Q1->Q2->Q3->Q4 lag by 45 deg each
tref = cross(dQ1 0 12 "rising")
sigs = list(dQ1 dQ2 dQ3 dQ4)
phErr = nil
for(k 0 3
  tk = cross(clip(nth(k sigs) tref tref+Tout) 0 1 "rising") - tref
  phErr = append(phErr list((tk - k*Tout/8.0)/Tout*360.0))
)

;; power
P = vdd * average(clip(-i("/V0/PLUS") t1 t2))

;; delay and PDP
tCK = cross(v("/CK") - v("/CKb") 0 25 "rising")
tQ  = cross(clip(dQ1 tCK tCK+T) 0 1 "either")
Td  = tQ - tCK
PDPfJ = P * Td * 1e15

printf("fout = %g Hz  ratio = %g\n" fout fout/fin)
printf("phase errors (deg) = %L\n" phErr)
printf("P = %g W   Td = %g s   PDP = %g fJ\n" P Td PDPfJ)

Syntax such as nth, append and the exact name of the current function (i("/V0/PLUS") versus iTime) must be checked against your OCEAN version; run the script in ocean -nograph -replay script.ocn after testing each expression once in the Calculator.

8. Sanity checks

  • Output frequency is fin/2 (ratio 0.500) and stays so for the whole window.
  • Each output swings between a low level and VDD with a differential peak of the order of 0.3 V (not 0 mV and not a full 1.0 V swing). A rail-to-rail swing means the resistive load is too large or the tail current too high.
  • Eight phases spaced by 45 degrees (Tout/8 apart); the sum of the eight consecutive spacings is 360 degrees.
  • Q and Qb are complementary and cross each other at the same instant (common mode stays near the mid-level).
  • Supply current is a repetitive wave with dc average of about P / VDD. A current of several mA at 45 nm points to a bias or biasing mistake.
  • Delay Td is smaller than a quarter of T (250 ps at 1 GHz, about 83 ps at 3 GHz); otherwise the latch is too slow for the target.
  • Results converge when errpreset is changed from moderate to conservative and when maxstep is halved; if not, the measurement is dominated by numerical error.

PVT corners and Monte Carlo

about 45 min Process, voltage and temperature changes the tail current, the load resistance and the switch resistance. A divider that works at TT/27 degrees C/1.0 V can fail at slow/hot/low-VDD. Run the corners in ADE Assembler, because it handles the model sections, variables and temperature in a single table.

1. Process sections

Use the section names your PDK provides. Inspect the model file to see them (command line, adjust the path from Setup > Model Libraries):

grep -n "^[[:space:]]*section" /path/to/gpdk045/models/spectre/gpdk045.scs

Typical names are typical, fast and slow sections, possibly with separate MOS and resistor/capacitor sections (verify). Resistor and capacitor corners matter here because R1 and R2 set the swing. If the PDK offers combined skew corners (slow NMOS fast PMOS) they have little meaning for an NMOS-only circuit, but keep the global corners.

2. Build the ADE Assembler setup

  1. In the testbench library: Launch > ADE Assembler and create a new view (for example maestro). Add the design tb_divider (the Assembler "Design" field).
  2. Copy the global variables from the cellview and add the analysis: tran with the same settings as in the testbench section.
  3. Copy your output expressions into the Outputs table: fout, ratio, phase errors, maximum phase error, P, Td, PDP. Give each a name and set a Spec (for example ratio from 0.495 to 0.505; maximum phase error below 10).
  4. Open the Corners setup (Setup > Corners or the Corners tab; verify in your version). Click "Click to add corner" and create one corner per row, or use the multi-value form for a full grid:
    Corner fieldValues
    Temperature-40, 27, 125
    Variable vdd0.9, 1.0, 1.1 (that is, +/-10 %)
    Model file section (process)typical, fast, slow (names from your PDK)
    Set the model file to the PDK file and select the section per corner in the "Model Files" cell of each corner.
  5. Reduce a full grid (3 x 3 x 3 = 27 runs) to the physically meaningful extremes if time is limited, then run the whole grid for the final report.
  6. Run: Run > Single Run, Sweeps and Corners (verify), or the green play button. Check the "Corners" box in the run mode.

Scale the stimulus with VDD The clock vpulse amplitude must follow vdd (set v2 = vdd), and the bias vb should track it if it is generated by a divider or mirror on chip. A fixed bias (for example 0.8 V) at 0.9 V VDD changes the headroom of M7; decide whether the bias is a fixed external source or derived, and say so in the report. Also keep the ic values valid: the high level is vdd, so use expressions where possible.

3. Export results

  1. Open the Results tab in Assembler after the run. Each corner is one column or row.
  2. Export with Results > Export (or the table's right-click menu or the export icon; verify in your version). Choose CSV, include all outputs and corner conditions.
  3. To make a plot of fmax vs corner, open the CSV in a spreadsheet or Python. Save the CSV in the project repository under a results directory.
  4. Capture the Assembler result summary screenshot with pass/fail colours for the report.

Optional: Monte Carlo mismatch

  • In Assembler: switch the run mode to Monte Carlo Sampling (verify the name in your version). Number of points N = 100 to 200, sampling random or low-discrepancy.
  • Select mismatch only (local variation) first. This is what degrades the phase error through M1/M2 and M3/M4 differences. Add process and mismatch as a second run if the PDK statistical models support it (verify that the model file has statistical or Monte Carlo sections).
  • Run at the nominal corner. The simulations take N times longer, so use errpreset = moderate and shorter windows (about 25 input periods).
  • Plot a histogram of the max phase error and of fout/fin (Results > Histogram, verify). Report mean, standard deviation and the fraction of runs that still divide. Larger device area (W and L, or more fingers) reduces mismatch; use this as a design trade-off argument.

A working order when everything seems broken First simulate a single DLATCH with a static D and a clock (verify that it follows D when CK is high and holds when CK is low). Then close the ring. Then add ic. Then lower fin to 1 GHz and increase step by step. This isolates schematic errors from start-up and speed limits, and it is much faster than debugging the four-latch loop directly.
