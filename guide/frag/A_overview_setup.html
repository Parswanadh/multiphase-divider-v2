1. Overview, deliverable map and 40-minute plan

1.1 What you are building

You are implementing the compact multiphase divide-by-two frequency divider of Kuo et al. (IEEE Microwave and Wireless Technology Letters, May 2025) in Cadence Virtuoso using the gpdk045 (45 nm) generic PDK. The divider is a ring of four cascaded differential CML-style D-latches driven by a complementary clock pair CK / CKb. The four latches are connected with alternating cross-couplings so that the ring behaves as a divide-by-two with eight equally spaced output phases at fin/2.

  • Latch cell (identical x4): sample pair M1/M2 (inputs D, Db), hold pair M3/M4 (cross-coupled), clock switches M5 (gate = CK) and M6 (gate = CKb), tail transistor M7 (NMOS in saturation, longer channel, gate on a DC bias Vbias), and load resistors R1, R2 to VDD.
  • Ring connections: Q1b to D2, Q2 to D3, Q3b to D4, Q4 to D1b. This single inversion around the ring (with the clock-phase alternation) produces the divide-by-two behaviour.
  • Outputs: eight phases named f0, f45, f90, f135, f180, f225, f270 and f315, each at fin/2 and spaced by 45 degrees of the output period, i.e. T_out/8 = T_CK/4 (since T_out = 2 T_CK). Verify this spacing in your own simulation by measuring the delay between adjacent phases.
  • Original paper values (180 nm CMOS): M1 to M6 = 0.9 um / 0.18 um, M7 = 1.8 um / 0.36 um, R1 = R2 = 1.5 kOhm, VDD = 1.8 V, fin = 1.4 GHz, total power 2.34 mW.
Scope of this guide This guide takes you from an empty directory to a simulated, characterised and (at least partially) laid-out design. Every numeric value in the specification section is a starting point. The deliverable is a design you tuned yourself with your own simulation evidence, not a copy of these numbers.

Your gpdk045 current will differ: adjust Vbias, R or M7 W until the swing is 0.4 to 0.5 V and Q, Qb separate cleanly.

2.4 Elmore delay model

The paper estimates the latch propagation delay with a first-order Elmore model. Follow the paper's own definitions of the capacitance breakdown and cross-check them against the figure/text in the paper before quoting them in your report; the compact summary is:

  1. Let C be the unit capacitance (one transistor drain/gate capacitance contribution) of the circuit.
  2. The common node a (the node shared by the sample/hold pair above the clock switches) is treated as a small-signal ground in the differential half circuit during the transition. Its diffusion capacitance, 2C, therefore does not charge through the load and does not contribute to the output delay.
  3. The total capacitance that must be charged or discharged at the output node is 8C (diffusion of the connected devices plus gate load of the following latch and wiring, as counted in the paper).
  4. The effective resistance seen charging that capacitance is R/2, per the paper's half-circuit model.
t_pdf = t_pdr = (8C) · (R / 2) = 4RC
Td ≡ t_pd = 4RC

Since the divider is a ring of four latches clocked on alternate phases, each clock half-period must be long enough for two latch delays to propagate (the signal ripples through two latches within one half-cycle of CK). Hence the timing condition:

T_CK / 2 > 2 · Td   ⇒   fin,max < 1 / (4 Td) = 1 / (16 R C)

So the maximum input frequency is limited by two latch delays, not by one. Use this as a sanity check: after you measure Td in simulation, compute 1/(4 Td) and compare it with the highest frequency at which your simulation still divides correctly. Differences are expected (finite edge rates, nonlinear devices, clock loading) and should be discussed in the report, not hidden. Note that the formula says reducing R lowers delay but also lowers swing at fixed Itail, so R and tail current must be tuned together.

Measure C instead of guessing it After your first run you can back out an effective RC from the measured delay (C_eff = Td / (4R)) and compare it with the value you would expect from device capacitances in the DC operating point (Results > Print > DC Operating Points, look for cgs, cgd, cdb parameters). This gives you material for the 8-mark sizing-concept answer.

3. Cadence environment setup

All paths below are placeholders. Your lab or workstation will have its own install and PDK locations. Where a name or path is marked "verify", do not guess: confirm it yourself with the commands shown.

3.1 Launching Virtuoso

  1. Open a terminal and create a clean working directory outside the PDK, for example: 
    mkdir -p ~/cadence/divider45
cd ~/cadence/divider45
  2. Source the Cadence environment script supplied by your lab (name and location vary; ask your administrator or look at the lab handout). Example only: 
    source /path/to/cadence_setup.csh      # or: . /path/to/cadence_setup.sh
  3. Check the tools are on your path: 
    which virtuoso spectre
spectre -W        # prints the Spectre version if the licence is reachable
  4. Start Virtuoso from the working directory (it reads cds.lib from the directory you start in): 
    virtuoso &
    The CIW (Command Interpreter Window) appears. Always keep this window visible: errors and netlisting messages show up in it.

3.2 cds.lib

The file cds.lib in the working directory tells Virtuoso where libraries live. The PDK usually provides either a ready-to-include file or just a library directory. Look at what you were given and use one of these forms:

# Option A: include the PDK's own cds.lib fragment (path is an example; verify)
INCLUDE /path/to/gpdk045/cds.lib

# Option B: define the PDK libraries yourself (verify the library names present in the PDK)
DEFINE gpdk045 /path/to/gpdk045/gpdk045
DEFINE analogLib $CDS_INST_DIR/tools/dfII/etc/cdslib/artist/analogLib
DEFINE basic     $CDS_INST_DIR/tools/dfII/etc/cdslib/basic

# Your own working library (created from Virtuoso in 3.3 and added automatically)
DEFINE div45 ./div45
Library names The exact name of the PDK technology and device library (for example gpdk045) and the location of analogLib/basic differ by installation. Verify in the Tools > Library Manager window that gpdk045 appears and that you can browse a cell such as the NMOS device. If the library is missing, fix cds.lib first and restart Virtuoso (or use Tools > Library Path Editor).

3.3 Creating your library attached to the technology library

  1. In the CIW choose File > New > Library (or in Library Manager File > New > Library).
  2. Name: div45. Directory: your working directory. Click OK.
  3. In the technology dialog choose Attach to an existing technology library (not "Compile a new technology library") and select gpdk045. This is what gives your cells access to layers, devices and the layout rules.
  4. Confirm in Library Manager that div45 exists and that Tools > Technology File Manager (or Tools > Technology File Manager > Attach) shows the technology as attached to gpdk045.
  5. Create the cells: File > New > Cell View with Library = div45, Cell = latch, View = schematic, Type = Schematic (Tool: Schematic L / Schematic XL depending on licence). Repeat for div2_top and later tb_div2.

Resistor choices

For R1 and R2 you have two practical options:

  • Ideal resistor (res from analogLib): simplest for the first simulation and for exploring the design. It has no parasitic capacitance and no layout, so it cannot be used for LVS/layout unless you replace it later.
  • PDK resistor (polysilicon or diffusion resistor PCell in gpdk045): needed for layout and LVS. Suggested workflow Use the ideal res from analogLib for the first transient and tuning. When the sizing is settled, replace it with the PDK resistor (set to the same value), re-run once, and note the difference. Only then draw layout. This keeps schematic-level debugging fast.

3.5 Finding the model file and corner sections

Spectre needs the model file of the PDK and a corner section name. Do not guess either: find them.

  1. Locate the PDK root (the directory you used in cds.lib, or ask your administrator). List its top level: 
    ls /path/to/gpdk045
ls /path/to/gpdk045/models        # a models directory is typical; verify
ls /path/to/gpdk045/models/spectre
  2. Find Spectre model files directly: 
    find /path/to/gpdk045 -name "*.scs" -o -name "*.lib" -o -name "*.inc" | head -50
  3. List the corner sections inside the model file (section names are PDK-specific; read them from the file): 
    grep -n -i "section" /path/to/gpdk045/models/spectre/<modelfile>.scs
grep -n -i "include" /path/to/gpdk045/models/spectre/<modelfile>.scs
    Replace the path and file name with what find returned. Typical Spectre syntax is section name ... endsection, and a file is used as include "file.scs" section=name. The section names (typical, slow, fast, or something else) are whatever you see in the output.
  4. Read the PDK's own documentation (PDF or README in the PDK directory) for the recommended simulation conditions, temperature range and which sections to pair for worst-case speed and power. Write down the section names you plan to use for corners: tt-like typical, a slow and a fast section. Names to be taken from the file you just grepped, not from this guide.
  5. Check that the device model name used by nmos1v exists in the file (for example by grepping for the model name the schematic netlist uses, see 3.7).

3.6 Including the model in ADE

  1. Open the testbench schematic (tb_div2) and launch Launch > ADE Explorer (or ADE Assembler if your licence supports corners; the menus are similar).
  2. Choose Setup > Simulator and confirm Spectre.
  3. Choose Setup > Model Libraries (in ADE Assembler: Setup > Model Libraries or via the global-sources section of the Setup assistant).
  4. Click the browse icon, select the model file found in 3.5, then in the section field type the exact section name (typical) you read from the file. Enable the entry with the checkbox.
  5. Click OK and check Simulation > Netlist > Create then Simulation > Netlist > Display. The netlist should contain an include "..." section=... line for your model.
  6. For corner runs, create separate model-library entries per corner (or in ADE Assembler define corners in the Corners setup with model file, section, temperature and VDD). Do not rely on edited copies of the PDK files.

3.7 Netlisting and simulating: first sanity run

  1. Set the analysis: Analyses > Choose then Type = tran, Stop time = about 10 x T_CK (for example 3.3 ns at 3 GHz; extend later), accuracy option conservative (or tight reltol) for clean edges.
  2. Set the outputs: select the eight output nets and CK by clicking them in the schematic (Outputs > To Be Plotted > Select On Schematic), plus the supply current /vdd/PLUS for power.
  3. Run Simulation > Netlist and Run. If the netlister complains about a model, check section 3.5 again.
  4. Look at the Spectre log (Simulation > Output Log) for warnings about convergence or missing models before you look at waveforms.
  5. Apply an initial condition (Analyses > Choose, tran, ic via Simulation > Convergence Aids > Initial Condition, or a short initial pulse) if the ring comes up in a symmetric stuck state; a differential latch ring has an unstable equilibrium and a perfectly symmetric start may not break in an ideal simulation.
Symmetric start-up A perfectly symmetric ideal circuit can stay at its metastable point forever in Spectre because there is no noise. If the outputs never separate, give one node an initial condition (for example one output at VDD and its complement near VDD - swing) rather than changing the circuit. Document which initial condition you used.
