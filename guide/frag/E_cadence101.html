Cadence from zero

read first, 5 min This section assumes you have never opened Virtuoso. Menu names, shortcut keys and window layouts differ between Virtuoso releases (IC6.1.x and IC23.1 look quite different). Everything below that I am not certain about is marked verify in your version. If a menu item is not where I say, look in the neighbouring menu or use the search box that newer versions provide in the top-right corner of most windows.

Honesty note The values and names in this guide have not been run on a real gpdk045 installation by the author. The pre-check simulation used generic (non-gpdk045) models. Every device name (nmos1v), model file path, section name and parameter name must be confirmed in your own PDK install. All sizes and biases are starting points that you will tune, not final answers.

1.2 Starting Virtuoso

  1. Open a terminal and cd into your project directory. This must be the directory that contains the file cds.lib (the file that lists your libraries; the course or your lab setup normally provides one). Check with ls cds.lib.
  2. If your lab requires it, first source the setup script of your site (for example one that sets PATH and the licence server). Ask your lab support; the exact line is site specific.
  3. Type virtuoso & and press Enter. The trailing & puts it in the background so the terminal stays usable.
  4. Wait. The CIW appears after a few seconds to a minute. A licence error is printed in the terminal and/or the CIW.
  5. Always start Virtuoso from this same directory. If you start it from somewhere else it will not find your libraries (they will be missing in the Library Manager) and it may create a new empty cds.lib.
Mouse basics Left button: select, or click to place/confirm the current command. Middle button (in some setups): repeat/confirm or pop up a menu. Right button: opens a context (pop-up) menu on the object you click, or cancels in some modes. Mouse wheel: zoom (and with modifier keys, pan), verify in your version. Dragging a box with the left button on empty space selects everything inside it.

1.3 The library / cell / view idea

Analogy: think of a library as a folder on your disk, a cell as one design (one sub-circuit, for example DLATCH), and a view as one representation of that design, like the different file formats of a document:

  • schematic: the circuit drawing (this is what you build).
  • symbol: the box with pins you drop into other schematics.
  • layout: the physical mask drawing (not needed for this task).
  • config: tells the tools which view of each sub-cell to use when netlisting (mostly for mixed hierarchies; you can ignore it).
  • av_extracted: the extracted post-layout view with parasitics (only after layout and extraction).

So "the latch's schematic" is library divider_lib, cell DLATCH, view schematic. The PDK itself is another library (gpdk045) that contains cells such as the NMOS transistor, each with a symbol view. When you place a device you are placing "library / cell / view" of the PDK.

Why Check and Save matters Closing a window or just pressing the regular Save (File > Save) stores the drawing, but only Check and Save (Design > Check and Save) verifies connectivity and also updates the internal connectivity data that the netlister uses. A schematic that was drawn but not checked and saved may netlist an old version, or fail to netlist at all. Make it a reflex: after every few edits, Check and Save, then read the CIW.

Tutorial: build ONE latch schematic from nothing

about 15 min Goal: a cell DLATCH in a new library divider_lib, with 7 NMOS transistors M1..M7, 2 load resistors, 9 pins, and a symbol. You will then reuse it four times.

Circuit in one paragraph This is a differential (current-mode-logic style) D-latch. R1 and R2 pull the outputs Q and Qb up to VDD. The sample pair M1/M2 (gates D and Db) steers current while the clock switch M5 (gate CK) is on; the hold pair M3/M4 (cross-coupled: gate of M3 is Qb, gate of M4 is Q) keeps the state while the opposite switch M6 (gate CKb) is on. M7 is the tail current source, biased by NBIAS. The cross-coupled pair needs loop gain gm*R greater than 1 to regenerate, so the load resistor must not be too small.

2.1 Create the library

  1. In the CIW choose File > New > Library (verify in your version; in the Library Manager the same entry is under its own File menu).
  2. In the "New Library" form type Name divider_lib. Leave the directory as proposed (your project directory) so the library is created next to cds.lib. Click OK/Apply.
  3. A second form asks about technology: choose Attach to an existing technology library and click OK.
  4. In the "Attach Design Library to Technology Library" form, set the Technology Library drop-down to gpdk045. The exact name depends on your PDK installation (it could be gpdk045 or a variant): verify the name in your list. If the list is empty or has no 45 nm entry, your cds.lib does not include the PDK; ask your lab support (the PDK must be defined in cds.lib via an INCLUDE or DEFINE line).
  5. Click OK. Read the CIW: a line about the new library and the tech attach should be shown, with no error.
  6. Open the Library Manager (Tools > Library Manager). Click divider_lib in the left column. It is still empty.

2.2 Create the DLATCH cell

  1. With divider_lib selected, choose File > New > Cell View (the Library Manager menu; verify in your version).
  2. Library: divider_lib. Cell: DLATCH (all capitals, to match this guide). View: schematic. Type: set to schematic (the Tool field is often filled automatically as "Composer-Schematic" or "Schematic L/XL"; accept the default).
  3. Click OK. An empty Virtuoso Schematic Editor window opens. Maximise it. Click once inside the drawing area to give it focus.
  4. Immediately press Shift+X to Check and Save once, so that the cell exists on disk.

2.3 Place the seven transistors M1..M7

  1. Press i. The "Add Instance" form opens.
  2. Click Browse. The Library Browser opens. In the Library column click gpdk045. In the Cell column find nmos1v (the 1.0 V NMOS in the usual gpdk045 naming; verify the cell name in your PDK, and do not use the thick-oxide device, which is typically named nmos2v). Click the symbol view. The form fields Library / Cell / View fill in. Close the browser.
  3. The form now shows the instance parameters of the device (typically width, length, number of fingers; the exact names come from the PDK's CDF, so read them in the form; verify). Type the starting values: W = 240n, L = 45n. Leave fingers at 1.
  4. Move the mouse to the drawing area. A ghost of the transistor follows the cursor. Press r to rotate if you wish. Click once to drop one device.
  5. Click six more times to drop six more copies (the command stays active). Press Esc when done. You now have seven NMOS instances, probably named M0, M1, ... or I0, I1 ... automatically.
  6. Arrange them roughly like this (any layout is fine, this one keeps wires short):

        |                 |

  7. Rename each instance: click a transistor to select it, press q. In the Edit Object Properties form set "Instance Name" (some versions show "Name") to M1, M2, ... M7 matching the table in 2.5. Click OK.
  8. Select M7 and press q; set W = 480n, L = 90n. The other six stay at W = 240n, L = 45n. Check each one by reselecting it and pressing q again, because a wrong value here costs minutes later.

2.4 Place the two load resistors

  1. Press i, click Browse, library analogLib, cell res, view symbol. Set Resistance to 8k (start value, to be tuned). Place two copies and name them R1 and R2 with q.
  2. analogLib res is an ideal resistor and is acceptable for a quick start. gpdk045 also provides its own resistor cells (poly or well resistors, names vary): verify in your PDK's library browser and switch to one of them before layout. An ideal resistor has no parasitic capacitance and no layout, so it cannot be used in layout-versus-schematic.
Why the load is 8k and not 1.5k In a generic-model pre-check (explicitly not gpdk045) a load of 1.5 kOhm was too small: the cross-coupled pair needs loop gain gm*R greater than 1 to latch and hold, and with the small resistor the latch did not regenerate. 8 kOhm is therefore the starting value here. Other documents in this project may say 1.5k; treat the number as a tunable parameter, check the DC drop (tail current times R must leave the outputs enough above ground to keep M1..M6 in saturation), and re-tune with gpdk045 models.

That is 9 devices in all (7 transistors plus 2 resistors). Net names (xs, xh, tail) are internal; pin names are the 9 external ones.

  1. Press w. Click on the first terminal (the small square/diamond at a device's drain, gate, source or bulk end), move to the second terminal and click again to finish the wire; double-click or press Esc to end the wire command. Wire one net at a time.
  2. To branch a wire from the middle of another wire, click on the existing wire where you want the junction, then continue to the destination. A solid dot appears at the junction; if there is no dot, the connection did not happen.
  3. Start with net Q: wire R1's bottom terminal to the drains of M1 and M3. Name it: press l, type Q in the Add Wire Name form, then click on the wire. The name appears next to the wire.
  4. Do the same for Qb (R2 bottom, M2 drain, M4 drain), then xs (M1 source, M2 source, M5 drain), xh (M3 source, M4 source, M6 drain), tail (M5 source, M6 source, M7 drain).
  5. Cross-couple M3/M4: the gate of M3 connects to net Qb; the gate of M4 connects to net Q. To avoid a mess of long crossing wires, you can just put a short stub of wire on each gate and label the stub Qb or Q with l. Equal names are connected, even if there is no visible wire between them. (The Check step will confirm this.)
  6. Put short labelled stubs on the remaining gates: M1 gate D, M2 gate Db, M5 gate CK, M6 gate CKb, M7 gate NBIAS.
  7. Bulk and VSS: wire the bulk terminal of each NMOS and the source of M7 to a net labelled VSS. Wire the top of R1 and R2 to a net labelled VDD.

2.6 Place the pins

  1. Press p. The Add Pin form opens.
  2. Type the pin names in the "Pin Names" field separated by spaces and choose the direction in the drop-down. Do it in groups:
    Pin namesDirection
    D Db CK CKb NBIASinput
    Q Qboutput
    VDD VSSinputOutput
  3. For each group, click in the drawing area once per name to drop the pins. They snap to the wire stubs you drew: drop each pin so that its small connection point touches the end of the correct labelled wire, or simply drop it close and wire it. A pin name that equals an existing net name is connected to it.
  4. Pin direction is cosmetic for simulation but matters for tidy symbols and for checking tools; pins on VDD/VSS are usually inputOutput.
  5. Pin names are case sensitive: Qb is not QB. Use exactly the names in the table; they are the same as in the reference netlist spectre/divider_gpdk45.scs.

2.7 Visual checks before saving

  1. Press f to fit the view, then zoom in on each device and look at its four terminals. Every terminal needs a wire ending exactly on it (no gap).
  2. Count the net names: you should see exactly Q, Qb, xs, xh, tail, D, Db, CK, CKb, NBIAS, VDD, VSS. Any other name (for example automatically generated net1) means an unlabelled or accidentally separate segment.
  3. Click each net name on the drawing: the whole net highlights. If only a piece highlights, your wire is broken into separate nets.
  4. Reconfirm all W and L values by selecting the instance and pressing q. Reconfirm the bulk pins go to VSS.

2.8 Check and Save and how to read it

  1. Press Shift+X, or choose Design > Check and Save.
  2. Look at the CIW (and, if the schematic window shows one, the status line at the bottom). The result is something like "Extracting connectivity ... Schematic check completed with 0 errors and 0 warnings" (exact wording differs by version).
  3. Errors (red markers in the schematic): must be fixed. Typical ones: duplicate instance name, shorted wires with two different labels, a pin bound to a different net.
  4. Warnings (yellow markers): read each one. Meaning of the common ones:
    • "Dangling wire" or "floating wire": a wire end connected to nothing; delete the stub or connect it.
    • "Net has only one connection" / "floating net": a label that connects to nothing else; probably a typo in a net name.
    • "Pin not connected": a pin with no wire.
    • "Two names for one net": two labels on the same wire; keep one.
    Warnings do not always block simulation, but warnings you do not understand are usually real mistakes.
  5. Use Check > Find Marker (verify in your version) to jump to a marker, or click a marker to see its message.

2.9 Create the symbol

  1. In the DLATCH schematic window choose Create > Cellview > From Cellview (verify in your version).
  2. The "Cellview From Cellview" form shows From View schematic, To View symbol and Tool/Type "SchematicSymbol". Click OK.
  3. The "Symbol Generation Options" form appears. Position the pins: the left side usually receives inputs (D, Db, CK, CKb, NBIAS), the right side outputs (Q, Qb), the top VDD, the bottom VSS. Click OK.
  4. The Symbol Editor opens, showing a box with pin stubs. Drag pins and the box outline only if you wish; leave pin names alone. A neat symbol saves time later when you wire four instances.
  5. Tidy it: you may enlarge the box a little so labels do not overlap; do not delete the selection-box or the instance-label placeholders (they carry the instance name).
  6. Check and Save the symbol with Shift+X (in the Symbol Editor too; verify in your version), then close the symbol window. In the Library Manager you should now see under divider_lib / DLATCH two views: schematic and symbol.
If you change the pin list later Adding or removing a pin in the schematic does not update the symbol automatically. Re-run Create > Cellview > From Cellview and let it update the symbol, then check that any higher-level instances still connect correctly.

2.10 Build divider_core from four latch symbols

  1. Library Manager: File > New > Cell View, Library divider_lib, Cell divider_core, View schematic.
  2. Press i, Browse, library divider_lib, cell DLATCH, view symbol. Drop four instances and name them XD1, XD2, XD3, XD4 with q.
  3. Wire the pins following the table below, and label each net with l. Put the divider_core pins listed after the table.

2.11 divider_core pin-by-pin table

Interconnect rule: the data pair of each latch comes from the previous latch's outputs. Q1b goes to D2; Q2 goes to D3; Q3b goes to D4; Q4 goes to D1b (that is, latch 1 receives D = Q4b, Db = Q4). Latches 2 and 3 receive swapped clocks (CK pin to the net ckb, CKb pin to the net ck); latches 1 and 4 receive the normal clocks.

The core's own pins: inputs ck ckb nbias, outputs Q1 Q1b Q2 Q2b Q3 Q3b Q4 Q4b, inputOutput vdd VSS. Net names in the table that look lower-case (vdd, ck) are the names used in the reference Spectre netlist; keep your capitalisation consistent with whatever you use at the testbench. In the testbench the ground reference must be the global node 0 (placed with a gnd symbol), so that the core's VSS pin is wired to it. Run Check and Save, then create the symbol view for divider_core exactly as in 2.9.

Why the swap? Latches 2 and 3 are clocked with the opposite phase from 1 and 4, so that data passes through alternately and the ring behaves like a master/slave chain with the inverted feedback from Q4 to D1b. If you forget the swap, or if one inversion is missing, the ring will not toggle. If the circuit does not divide later, re-read this table before anything else.

  2. Connect VSS of the core to gnd.
  3. Add the eight 10 fF capacitors from each output net to gnd.

3.5 Setup > Model Libraries

  1. Choose Setup > Model Libraries (verify in your version; in Explorer it may be a tab/section called "Model Libraries" or a toolbar item).
  2. In the form, click the browse icon or type a path in the "Model Library File" field. Point it to the gpdk045 Spectre model file.   4. Click Add so the line appears in the list and tick it to enable it, then OK.

3.6 Analyses > Choose > tran

  1. Choose Analyses > Choose (verify in your version; in Explorer, use the Analyses pane and the + button).
  2. Select tran (transient analysis).
  3. Stop Time: 40n for the first run (40 cycles at 1 GHz, enough to see several division periods). If a run is slow, shorten it.
  4. Accuracy Defaults (errpreset): conservative is a good starting choice, you can relax it to moderate later (verify in your version).
  5. Maximum step: if the form shows it, 5p is a safe starting value to resolve 20 ps edges.
  6. Tick Enabled, then OK. The analysis now appears in the analyses list with a tick.

3.7 Outputs: select nets from the design

  1. Choose Outputs > To Be Saved > Select On Design, or Outputs > Setup and the "Select from design" button (verify in your version).
  2. The schematic window comes to the front. Click on the net wires ck, ckb, Q1, Q1b (click each wire once; the name is added to the outputs list). Add the rest (Q2 ... Q4b) if you want to see the whole chain; the more signals you save, the larger the results file.
  3. Click the pin of the supply source VDD if you also want the supply current.
  4. Back in ADE the "Outputs" pane lists the signals. Ticking "Plot" means they open automatically after the run.
  5. Make sure you click on wires (nets) for voltage and on the terminal of a device for current. Clicking a device body selects an instance, not a net.

3.8 Initial conditions

A symmetric differential ring can sit exactly at the metastable point and never start dividing. Give it a defined starting state: Q1 and Q2 high, Q3 and Q4 low (and the complements the other way).

  1. In ADE look for Simulation > Convergence Aids > Initial Condition (older ADE L) or the "Initial Condition" entry in the Setup menu (verify in your version). In Explorer or Assembler it may be in the Setup or Simulation Options area; if you cannot find it, use the search box and type "initial".
  2. In the form click Select Node (or similar), then click the net in the schematic; a row appears with the node name. Enter the value in the value field.
  3. Enter the following, to match the reference netlist (ic Q1=1.0 Q1b=0 Q2=1.0 Q2b=0 Q3=0 Q3b=1.0 Q4=0 Q4b=1.0):
    NetQ1Q1bQ2Q2bQ3Q3bQ4Q4b
    Initial V1.001.0001.001.0
  4. Click OK. The values are written to the netlist as ic statements. If your ADE only offers "Nodeset" (Convergence Aids > Nodeset), nodeset is a hint to the DC solver and is less strict than ic; for a transient start ic is what you want. Verify in your version.
  5. After the run, open the netlist (3.10) and search for ic to confirm the line is present. If it is missing, the initial conditions were not applied.
  6. Judge division from cycles after the start-up transient rather than the very first edge.

3.9 Netlist and Run

  1. Press Shift+X in the testbench to Check and Save again, and also re-save DLATCH and divider_core if you modified them.
  2. In ADE choose Simulation > Netlist and Run, or click the green play button in the toolbar. In ADE Assembler the button might be "Run".
  3. Watch the CIW and the ADE status bar. The status first shows "netlisting", then "running", then "finished". A short transient for 40 ns should finish in seconds to minutes.
  4. If a pop-up shows errors, do not close it; read it, then open the log (3.10).

3.10 Where the netlist and the log live

  • View the netlist: Simulation > Netlist > Display (verify in your version). A text window shows the generated Spectre netlist: look for your include line with the model file and section, 4 instances XD1 ... XD4 of DLATCH inside a subcircuit, the vpulse sources, the capacitors and the ic line.
  • View the Spectre log: Simulation > Output Log (verify in your version). Read it from the top: the first ERROR line is the real problem; later errors are consequences.
  • The files are also on disk, in a directory like simulation/tb_divider/spectre/schematic/netlist/ under the simulation root (typically ~/simulation); the exact tree depends on your version and your setup. The file you want is called input.scs; the log is spectre.out in the run directory. Verify the location in your version.

3.11 Plot the results

  1. After a successful run choose Results > Direct Plot > Main Form (verify in your version; in Explorer, plot is often automatic or the outputs listed in the Outputs pane are plotted with the "Plot after simulation" checkbox).
  2. In the form select Analysis = tran and Function = Voltage.
  3. Click the net in the schematic (ck first, then Q1). To plot Q1 minus Q1b as one differential curve, use the Calculator instead (see the waveform basics below).
  4. Press Esc to end selection after clicking the last net, then Plot (or middle click).
  5. The Waveform Viewer opens.

3.12 Waveform viewer basics

  • Zoom: in the toolbar choose the zoom tool and drag a box in the plot area; the f key fits all data in the window (verify in your version). The View menu offers zoom in/out and reset.
  • Markers: Marker > Create Marker (verify), click on a waveform to place a marker. Place two markers and use the "Delta" (a "Create Delta Marker" or dx readout) to read a time difference: the period of CK and the period of Q1.
  • Strips: by default all curves are in one plot. Use Axis > Strip > Add or the "Split Current Strip" / "Add Strip" toolbar buttons (verify), then drag a curve into the new strip to stack the clock above the outputs. Stacked strips share the same time axis.
  • Add axis: if two quantities have different ranges (for instance voltage and current), use Axis > Add Axis / "Add Y Axis" (verify) so each has its own scale.
  • Calculator: open Tools > Calculator (verify). Click vt (voltage versus time) and then on a net in the schematic; the expression is built in the buffer. Click - after a second net, to build Q1 minus Q1b, then Plot.
  • Delete / hide: select a curve, press Delete, or toggle its visibility in the legend.

3.13 How to tell "it is dividing"

f(Q1) = f(CK) / 2, equivalently period(Q1) = 2 x period(CK)
  1. Plot ck (top strip) and Q1 (second strip) over the same time range.
  2. Put marker A on one rising edge of ck and marker B on the next rising edge: the delta is the clock period (1 ns for a 1 GHz clock).
  3. Put marker A on one rising edge of Q1 and marker B on the next rising edge of Q1. If the delta is twice the clock period (2 ns), the circuit divides by 2.
  4. Also confirm that Q1 and Q1b are complementary and swing by a reasonable amount (do not trust a plot where the swing is a few millivolts; in that case the latch is not regenerating, so re-check R and bias).
  5. The 8 phases: Q1, Q1b, Q2, Q2b, Q3, Q3b, Q4, Q4b should be evenly spaced in time within one output period. Placing delta markers between corresponding edges gives the phase spacing, ideally one eighth of the output period. I give no target numbers here because none were measured on gpdk045; the measured spacing is your result.
  6. If instead the outputs are static, or toggle at the same rate as the clock, or ring at a strange frequency, return to the cheatsheet in the Cadence from zero section and also try (a) a lower fin (500 MHz), (b) larger load R, (c) higher or lower VB, (d) tight accuracy and maximum step.
Starting values, not results VDD = 1.0 V, M1..M6 at 240n/45n, M7 at 480n/90n, load R about 8k, VB about 0.8 V, 10 fF per output, fin = 1 GHz, clock edges 20 ps. These come from a pre-check that was NOT run with gpdk045 models. Expect to tune the bias, the load and the sizes. Do not quote them as findings.

4.2 Fallback path: the standalone Spectre netlist

The repository contains a ready-written Spectre netlist, spectre/divider_gpdk45.scs. It contains the same circuit as the tutorial (DLATCH subcircuit with M1..M7, R1/R2 at rl=8k, four instances with the swapped clocks, pulse sources at 1 GHz, 10 fF loads, initial conditions and a 40 ns transient). It does not need the schematic to exist. Use it (a) if the schematic route fails or runs out of time, (b) to cross-check your schematic-generated netlist (compare the two with a text diff).

Untested against the real PDK The author's machine has no gpdk045 installation, so this netlist has never run against the real PDK. The device name nmos1v, the include path and the section name are guesses marked VERIFY in the file. Treat any error as a probable naming issue first, not a circuit problem.
  1. Open a terminal in the repository directory (this one has no Cadence GUI dependence, only the environment that makes the command spectre available; ask your lab support if which spectre prints nothing).
  2. Open the netlist in a text editor and find the line marked VERIFY: 
    include "/path/to/gpdk045/models/spectre/gpdk045.scs" section=typical   // VERIFY
    Replace the path with the real model file path from step 3.5 and the section with the real section name. Keep the quotes.
  3. Check the device name on the lines starting with M1 ... M7. If your PDK names the 1.0 V NMOS differently from nmos1v, replace it in the seven lines (a global find/replace is fine). Also check that the model's parameters accept w and l as given; if the PDK models use fingers, nf or multiplicities with different parameter names, adapt (verify in the model file).
  4. Run it: 
    cd spectre
spectre divider_gpdk45.scs +log run.log
    This writes the log into run.log and the raw results into a directory called something like divider_gpdk45.raw (the name is derived from the netlist name; verify what is created on your machine).
  5. Read the log: grep -i error run.log | head. Fix the first error, rerun.
  6. View the waveforms. Either start viva from the terminal and open the results directory (File > Open Results, then choose the raw directory; verify in your version), or in Virtuoso ADE choose Results > Select > PSF Directory/Open Results (verify) and point it at the same directory, then plot Q1 and ck like in 3.11.
  7. The netlist saves Q1 Q1b Q2 Q2b Q3 Q3b Q4 Q4b ck ckb and the supply current. If you want other signals, edit the save line.
What this gives you, and what it does not A successful run of the standalone netlist shows that the model file, the device names and the topology work, and produces waveforms for the "is it dividing?" check on a real PDK. It does not replace the schematic: the task asks for a schematic, and the standalone netlist has no layout or extraction link. Use it as a safety net and as a reference to diff against your own generated netlist. The DLATCH sizes, R=8k and VB=0.8 are still starting points; the pre-check behind them used generic models, not gpdk045.

4.3 If it does not divide: a short debug order

  1. Is the swap right? XD2 and XD3 must have CK and CKb swapped; XD4's Q goes to XD1's Db.
  2. Is the initial condition applied? Check the netlist for ic.
  3. Does one latch alone latch? Temporarily simulate a single DLATCH with static D and a clock to check that the output follows D when CK is high and holds when CKb is high. If the output swing is tiny, loop gain gm*R is too small (raise R, W of M3/M4, or the bias current via VB); if the swing is huge but slow, reduce R or C.
  4. Is the tail current sensible? Look at the DC current of the VDD source (VDD:p in the standalone netlist) and the DC voltage of node tail; M7 must be in saturation (its drain-source voltage above its overdrive). VB at about 0.8 V is only a starting guess.
  5. Try a lower fin first (for example 500 MHz or 250 MHz) and raise it once division works.
  6. If everything fails, report exactly which of the above you checked and what you saw; a clearly documented failure is more useful than an invented success.
